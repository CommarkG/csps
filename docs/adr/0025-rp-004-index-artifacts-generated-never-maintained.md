# ADR-0025 — RP-004: Index Artifacts Are Generated Outputs, Not Source Files

## Context and problem statement

The CSPS platform has multiple "index" artifacts — files whose purpose is to list
all instances of something (L3 instance registries, audit-runner-index.yaml, etc.).
These were designed to be auto-generated by scripts, but the generation scripts were
deferred to "week-4" in S006 and never built. All 5 L3 instance registries said
"auto-populated by `tools/scripts/instance-registry-populator.mjs`" while
`tools/scripts/` contained only unrelated scripts. After 21 sessions, L3 files
listed ~5-10 artifacts per spine while the actual corpus had 227+.

Manual curation of derived content = guaranteed staleness. Opus Turn 16 SROF-008
confirmed this as a constitutional issue affecting the platform's architectural integrity.

## Decision

Any artifact whose purpose is to enumerate instances of a type (index artifact) MUST
be machine-generated, not hand-curated. This is now constitutional.

**Generated index artifacts declare in frontmatter:**
```yaml
generated: true
generated_by: <script-path>
manual_edits_forbidden: true
```

**Affected artifacts:**
- `.claude/core-spines/L3_INSTANCES_*.md` (5 files) → generated by `instance-registry-populator.mjs`
- `packages/principles/principles-index.yaml` → generated by `split.mjs`
- `docs/plan/pillar-0-governance/audit-runner-index.yaml` → generated by `split-audit-runner.mjs`
- Future: any file claiming to list "all instances of X" in the platform

**Enforcement:** `validate-generated-artifact-freshness.mjs` (to build Session B) will verify
that generated artifacts were regenerated within the session boundary of the files they index.

## Consequences

**Good:**
- L3 instance registries are now live (227 artifacts indexed vs. ~5-10 stale)
- Navigation from L2 domains to their instances now works correctly
- The "auto-populated by... (deferred week-4)" pattern is eliminated
- Index staleness is detectable and blockable

**Neutral:**
- Scripts must be run to update indexes (not automatic at file-save time)
- `instance-registry-populator.mjs` is one-shot initially; recurring via pnpm workflow planned

**Bad:**
- Pre-existing manually-edited content in L3 files is replaced (acceptable — content was stale)
