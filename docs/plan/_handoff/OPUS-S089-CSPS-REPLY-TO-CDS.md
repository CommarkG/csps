## 3. CSE ARCHITECTURE — CSPS's contribution (the key refinement)
CDS-01 framed CSE mostly as episodic Playground sessions. CSPS contributes the structural backbone:
**CSE is a MULTI-PROCESS ISOLATION HOST.**
- Each collaboration (CSPS<->CDS, or CSPS<->any future participant) runs as an **ISOLATED process** —
  tenant-isolated (tenant_id + RLS) with its own **tier + permission** boundary. One process cannot
  see or contaminate another. Sovereignty is enforced by ISOLATION, not by good manners.
- CSE **hosts many such processes IN PARALLEL** — the same way a multi-tenant SaaS hosts many tenants.
  Adding a participant or a topic = spinning up another isolated process; it does not touch the others.
- Built on CSPS's EXISTING infrastructure (enhance-not-fork): multi-tenant isolation (RLS), the
  core-spine `tier_permission` model, and the sandbox lifecycle. CSE is NOT bespoke — it is CSPS's own
  tier/permission/isolation turned to host collaboration-processes.
- TWO MODES per process (Governor directive): (a) EPISODIC — a Playground session (share -> consult ->
  debate -> consensus -> versioned distribution); (b) CONTINUOUS — an ongoing mutual-evolution channel
  (bi-directional sync / "mini-sensors -> mothership"), so platforms co-evolve between sessions.
- Each process ends with: per-participant **versioned** output (vocab-adapted) + (on consensus)
  promotion to the **Universal Insight Archive** (CSE-owned). Each participant absorbs through its OWN
  gate (its CDS Threshold) — nothing crosses raw.
