# 6. GE -- Cross-Session Context Restoration Protocol (Addendum to 1080)

GAP GE RESOLVED   Loop Orchestrator declares cycle exit state is passed forward but never defines the mechanism for loading that state at the start of a new session.
A loop that loses its accumulated state between sessions is not a loop -- it is a series of disconnected attempts at the same goal. Context restoration is what makes a loop a loop across session boundaries.
Restoration Step
Action
Failure Handling
1 -- Session start trigger
At the start of any session that continues an active loop -- the Loop Orchestrator is invoked before any other action
If Loop Orchestrator is not invoked -- session is classified as a new session, not a loop continuation
2 -- Loop state retrieval
Loop Orchestrator retrieves the Loop State record from the Loop State Registry using the Loop ID declared by the human or session initiator
If Loop ID not provided -- human is asked to declare it before session proceeds
3 -- Cumulative entry state injection
The cumulative entry state from the previous cycle is injected into the current session context as the first bundle element
If entry state is stale (wiring state = Defined) -- human is notified and asked whether to proceed with stale state or pause for state refresh
4 -- Remaining backlog retrieval
Priority Engine retrieves the remaining goal backlog from the previous cycle and re-scores against current platform state
Re-scoring is mandatory -- the platform may have changed between sessions
5 -- Resource Reality check
P5 check is run for the new session -- token window and human time are re-confirmed, not carried from previous session
Previous session's resource declarations never carry forward -- each session's resources are declared fresh
6 -- Continuation confirmation
Human confirms the restored context is accurate before the session proceeds
If human identifies inaccuracies -- they are declared and the entry state is corrected before proceeding

# 7. GF -- Vocabulary Injection Protocol (Addendum to 1000)

GAP GF RESOLVED   The vocabulary standard defines terms at three depths but never declares how vocabulary is loaded into an AI session.
Injection Rule
Definition
Vocabulary first
Vocabulary is always the first bundle element in any session -- loaded before any protocol document, any pipeline definition, or any element registry
Depth-matched injection
Vocabulary is injected at the depth level matching the session type: Core for mechanical tasks, Medium for standard builds, Full for governance sessions
Conflict declaration
When an AI engine's training vocabulary conflicts with a CSPS native term -- the CSPS definition takes precedence. The conflict is declared explicitly at session start: 'In this session, [term] means [CSPS definition], not [training definition].'
Vocabulary freshness check
At the start of every session -- the vocabulary version is checked against the current Vocabulary Registry. If a newer version exists, it is loaded. Stale vocabulary is not used.
New term handling
If a session encounters a term not in the vocabulary -- the term is flagged, the session continues with a declared assumption about the term's meaning, and the term is submitted to the Vocabulary Registry for formal definition

# 11. GJ -- Wizard Error Recovery Protocol (Addendum to 2000-2060)

GAP GJ RESOLVED   Wizard documents define only the happy path. No error recovery is declared.
Error Type
Definition
Recovery Protocol
Contradicted answer
Human provides an answer in step N that contradicts an answer given in step M
Wizard flags the contradiction, presents both answers, asks human to resolve. After resolution, all steps between M and N that depended on the original answer are re-executed.
Inconsistent output
A wizard step produces output that fails validation (backpack incomplete, gap detected, inheritance break)
Wizard declares the failure specifically, presents the inconsistency, returns to the step that produced it. Human and wizard resolve together before proceeding.
Step restart request
Human explicitly requests to restart from a previous step
Wizard confirms which step, warns which downstream steps will be invalidated, receives explicit confirmation, then restarts from declared step.
Resource exhaustion mid-wizard
Session resources are exhausted before wizard completion
Wizard produces a partial exit state -- what has been completed -- and declares it as a known partial. Loop Orchestrator saves the state. Next session resumes from where resources ended.
Goal drift
Human's goal statement shifts significantly during the wizard session
Wizard flags the drift, presents the original goal and the emerging goal, asks whether to update the goal object or continue with the original. If updated -- Wizard restarts from Step 1 of 2000 with the revised goal.

# 13. GL -- Priority Score Formula V2 (Correction to 0040)

GAP GL RESOLVED   The Priority Score formula includes P6 as an additive term with no defined range, making it unexecutable.
The corrected formula replaces P6 as an additive term with P6 as a weight multiplier applied to the combined P1-P4 score:
Formula Version
Formula
Notes
V1 (deprecated)
(P1xw1) + (P2xw2) + (P3xw3) + (P4xw4) + P5_gate + P6_adjustment
P6 had no defined range or calculation method -- unexecutable
V2 (current)
Base Score = (P1xw1) + (P2xw2) + (P3xw3) + (P4xw4) | Personalized Score = Base Score x P6_multiplier | P5 Gate: if P5 fails, action is removed from queue regardless of score
P6 is now a multiplier in range 0.5-2.0, derived from user weight configuration. Default: 1.0 (no modification). A user who heavily weights Ripple Effect sets a P6 multiplier that amplifies P1 contributions.
