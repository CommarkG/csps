# 14. P5.1 -- Continuous Loop Type Added to 1080

RESOLVED: P5.1   Loop Orchestrator (1080) now declares a fourth loop type: Continuous Loop.
CONTINUOUS LOOP   A Continuous Loop is a loop that runs indefinitely -- receiving inputs, processing them, and producing outputs -- without a declared termination condition. It does not converge on a goal. It does not refine toward a threshold. It does not explore an unknown space. It maintains a function continuously. It terminates only on explicit Platform Governor instruction or system shutdown.

RESOLVED: P6.1, P6.2, P6.3   Three missing vocabulary terms added to Document 1000 with full three-depth definitions.
Term
CORE Definition
MEDIUM -- Good/Bad/Measured
FULL -- Hidden Principle
Simulation
Validation of structural coherence -- connectivity and context -- applied to the conceptual model before any code exists. Finds gaps at 1x cost versus 10x at build time and 100x at production.
Good: six personas run against declared structures and produce zero findings before Sprint 1 begins. Bad: simulation skipped -- gaps discovered during build when they cost 10x. Measured by: gap density per persona pass, and whether findings were found at conceptual level or implementation level.
The elements are never where the problems are. The connections are. Simulation is the only mechanism that validates connections before they are built. Code can only validate what it implements -- it cannot see what is missing from what it implements.
Sprint (CSPS)
A GPOW loop cycle in the Corespiral Implementation Protocol. Not an Agile sprint. Each sprint has declared deliverables, a simulation gate, and cannot begin until the previous sprint's gate is clean.
Good: sprint begins after previous gate is confirmed clean, produces declared deliverables, ends with simulation that confirms gate status. Bad: sprint begins without gate confirmation, or produces deliverables but skips end-of-sprint simulation. Measured by: Simulation Gate Record status at sprint end.
A sprint that begins without a clean gate is not a sprint -- it is an escalation of unresolved problems. The gate is not a ceremony. It is the mechanism that prevents the corespiral from spiraling inward instead of outward.
Kernel (CSPS)
The minimum self-validating system -- the smallest set of components that enables everything else to be built correctly inside its validation loop. Not the minimum deployable system.
Good: kernel components can simulate themselves -- SK-ORCH-0001 and SK-GAP-0002 can validate the kernel's own backpack declarations. Bad: kernel defined as the smallest deployable system -- which may not be self-validating. Measured by: can the kernel run a Zero Findings check on its own components?
The kernel is not about minimalism. It is about self-reference. A system that cannot validate itself cannot safely build anything else. The kernel's defining property is that it is the first thing that can look at itself and say: this is structurally coherent.
