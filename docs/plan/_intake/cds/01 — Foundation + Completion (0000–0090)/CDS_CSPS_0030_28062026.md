# 1. Position in the System

What an agent is:  A declared, goal-directed executor that invokes skills in a governed sequence to achieve a defined outcome. An agent is a pipeline in motion -- it has a declared goal, a skill invocation sequence, accumulated context, and a resolution signal.
What an agent is not:  A skill. An agent does not know how to do things -- it knows which skills to invoke and in what order. An agent is not a general-purpose AI session. It is a declared, bounded executor with explicit authority, declared skill permissions, and a traceable audit trail.
Relationship to skills:  Skills are what agents invoke. Every agent has a declared skill permission list -- the set of skills it is authorized to call. An agent cannot invoke a skill not on its permission list. Permission is granted at definition time, not at invocation time.
Relationship to pipelines:  An agent IS a pipeline at execution time. The Pipeline Protocol (1010) defines the structure. The agent executes within that structure -- invoking skills at each stage, carrying accumulated context forward, and producing the resolution signal declared in the pipeline goal.
An agent that invokes a skill not on its permission list is a governance violation. An agent that invokes skills in a sequence not declared in its definition is an undeclared agent. Governance is enforced at definition -- not assumed at runtime.
ZERO FINDINGS MANDATORY   Before defining any new agent -- check the Agent Registry. An agent serving a similar goal with similar skill permissions may already exist. A new agent definition requires explicit justification that no existing agent covers this execution pattern.

# 2. The Three Agent Authority Levels

Agent authority determines how much autonomous decision-making power an agent has at branch points and at moments of uncertainty. Authority is declared at definition time -- not granted dynamically.
AGENT PRINCIPLE   Authority level is matched to depth level. A Core agent operating at human-in-the-loop authority is the safe starting point for any new agent. Authority is escalated deliberately -- not assumed.
Authority Level
Depth Match
Decision Behavior
Branch Handling
Vault Handoff
When to Use
CORE -- Human in the Loop
CORE depth
Every decision point requires human confirmation before proceeding. Agent presents its proposed action and waits.
Every branch presented to human. Agent does not select branch autonomously.
All findings immediately. No exceptions.
New agents, high-stakes pipelines, first execution of any agent definition, any agent touching sensitive data or governance decisions.
MEDIUM -- Confirmed at Branch Points
MEDIUM depth
Agent proceeds autonomously within declared stages. Pauses only at Decision Stage branch points for human confirmation.
Branch selection requires human confirmation. All other decisions are autonomous within declared constraints.
All findings at session end plus immediate handoff for gap discoveries.
Validated agents with established track records. Standard platform operations. Agents whose skill permission lists have been audited.
FULL -- Autonomous Within Constraints
FULL depth
Agent proceeds autonomously throughout the execution. Halts only when a gap or failure mode is encountered that is not covered by declared constraints.
Branch selection is autonomous -- guided by declared branch criteria in the pipeline definition. No branch is selected outside declared criteria.
Real-time. Every finding forwarded immediately. Every branch selection recorded.
Fully validated agents with complete audit trails. Governance sessions where the agent is executing a ratified protocol. Dynamic Completion propagation sessions.
Escalating from CORE to FULL authority is not a progression that happens automatically. It requires Platform Governor approval based on audit trail evidence. An agent that has not been audited at CORE authority cannot be granted FULL authority.

# 4. Agent Execution Protocol

Every agent execution follows a declared sequence. Deviation from this sequence is a governance violation. The Core Engine (3000) enforces this sequence at runtime.
Step
Action
Authority Level Behavior
1 -- Pre-execution Zero Findings
Check Agent Registry for existing executions of this agent on similar input. Check Skill Registry to confirm all permitted skills are at required wiring state.
All levels: mandatory. No agent begins without Zero Findings confirmation.
2 -- Context assembly
Receive entry state. Assemble accumulated context from entry state and any inherited context from the invoking session.
All levels: mandatory. Agent cannot proceed without declared entry state.
3 -- Skill invocation sequence
Invoke skills in declared order. Pass accumulated context to each skill. Receive output and add to accumulated context chain.
CORE: each invocation confirmed by human. MEDIUM: autonomous except at branch points. FULL: autonomous throughout.
4 -- Branch handling
At Decision Stage branch points -- evaluate branch criteria and select or present.
CORE: present all branches to human, wait for selection. MEDIUM: present branch selection to human, wait for confirmation. FULL: select branch autonomously per declared criteria, record selection in audit trail.
5 -- Gap monitoring
After each skill invocation -- check output for gap signals: inheritance breaks, wiring state mismatches, output contract violations.
All levels: mandatory. Gap signals halt the current step and are forwarded to vault before proceeding.
6 -- Resolution signal production
When all stages are complete -- produce the declared resolution signal. Verify it matches the Goal Declaration.
All levels: mandatory. An agent that completes without producing the declared resolution signal has not completed.
7 -- Audit trail production
Produce complete audit trail per the Audit Trail Template in the backpack. Forward to Dynamic Completion vault.
All levels: mandatory. An execution without an audit trail is an ungoverned execution.
8 -- Forward output
Pass resolution signal and accumulated context to declared Relationship Forward recipient.
All levels: mandatory. Output must match Forward Obligation declaration exactly.
AGENT PRINCIPLE   An agent that completes Step 6 without a resolution signal has not completed -- it has failed silently. Silent completion is the most dangerous agent failure mode. The audit trail in Step 7 is the mechanism that prevents silent completion from going undetected.

# 5. Agent Composition -- Multi-Agent Pipelines

Some pipeline goals require more than one agent executing in sequence. This is multi-agent composition. It is governed by the same principles as skill composition -- declared at definition time, coordinated by the orchestrator, never implicit.
Composition Rule
Definition
Enforcement
Sequential only
Agents in a multi-agent pipeline execute sequentially. No parallel agent execution without explicit Platform Governor approval and a declared coordination protocol.
Core Engine blocks parallel agent invocations not declared in the pipeline definition.
Explicit handoff declaration
Every agent-to-agent handoff is declared in the pipeline definition -- what the first agent passes, what the second agent receives, and how the accumulated context chain transfers.
Bundling Engine validates handoff declarations before releasing context to the receiving agent.
Authority level preservation
An agent cannot invoke another agent at a higher authority level than itself. A CORE agent cannot delegate to a FULL agent.
Agent Registry enforces authority level ceiling at invocation time.
No recursive agent calls
An agent cannot invoke itself or create a cycle in the agent invocation graph.
Core Engine detects cycles at session initialization and blocks execution.
Unified audit trail
A multi-agent pipeline produces a single unified audit trail -- each agent's trail is a chapter in the pipeline's complete trail.
Dynamic Completion vault receives the unified trail, not individual agent trails separately.
A multi-agent pipeline is still one pipeline serving one goal. The goal does not change when multiple agents serve it. The resolution signal is produced by the last agent and must match the pipeline's Q5 declaration -- not the last agent's individual goal.

# 6. The Agent Registry

Every agent defined using this standard is registered in the Agent Registry. The registry is the Zero Findings check target for all new agent definitions and all agent invocations.
ZERO FINDINGS MANDATORY   Before invoking any agent -- check the Agent Registry for the agent's current wiring state and authority level. An agent at CORE authority cannot be invoked as FULL. An agent whose skill permission list contains skills at Defined wiring state cannot be invoked at MEDIUM or FULL authority.

# 8. Audit Mirror

ZERO FINDINGS MANDATORY   Before auditing any agent execution -- retrieve the agent's declared Audit Trail Template. Audit against the declared template -- not against a generic checklist.

Audit Question

Does the Skill Permission List cover every skill invoked during execution? Any invocation outside the list is a violation.

Does the declared sequence match the actual execution sequence in the audit trail?

Do all branch selections in the audit trail match the declared branch criteria?

Did the agent produce the exact resolution signal declared in the Goal Declaration?
