## P2 -- Enablement Factor -- V2: Interaction Cap

PRIORITY PRINCIPLE   How many dormant or blocked things does this action bring to life? Actions that unlock other actions multiply their value beyond their direct output.
V2 addition -- P2/P3 interaction cap (PE-2): When both P2 > 70 AND P3 > 70, the combined P2+P3 contribution is capped at 80 points. Rationale: both parameters measure downstream leverage from different directions. Scoring above 70 on both indicates the same downstream effects are being counted twice.

# 3. Priority Score Formula -- V2

V2 corrected formula (PE-1, PE-2, PE-5):
Formula Step
Calculation
Step 1 -- Base score
(P1xw1) + (P2xw2) + (P3xw3) + (P4xw4) where weights sum to 100% (excluding P5 weight which gates, not scores)
Step 2 -- P2/P3 cap check
If P2 score > 70 AND P3 score > 70: replace combined P2+P3 contribution with min(combined, 80)
Step 3 -- P6 multiplication
Personalized Score = Base Score x P6 multiplier (0.5-2.0, default 1.0)
Step 4 -- P5 gate
If SK-ORCH-0005 resource check fails: action removed from queue regardless of score. P5 does not add to score.
Step 5 -- Threshold check
If Personalized Score < 35: action is parked with reason. If >= 35: enters execution queue in score order.
Tiebreaker
Equal scores: P4 (Readiness) is the tiebreaker. Simpler, more certain action executes first.
Threshold derivation (PE-1): The 35 threshold is a governance choice -- not a mathematical minimum. It declares that an action must achieve at least Standard ripple (P1>=40) AND Mostly Ready readiness (P4>=50) to qualify. An action with zero enablement, zero gap resolution, Standard ripple, and Mostly Ready readiness scores approximately: (40x0.20)+(0)+(0)+(50x0.20) = 8+10 = 18x1.0 = 18. The threshold of 35 is therefore set above the minimum useful score, ensuring actions that enter the queue have meaningful value.

# 4. Mini Priority Engine -- Unchanged

The Mini Priority Engine governs execution order within a single session. It inherits from the Platform Priority Engine and elevates P5 weight to 30% minimum for session-level scoring. All V2 changes to P2/P3 cap, readiness threshold, P5 executor, weight validation, and re-scoring triggers apply to the Mini Priority Engine identically.
