# 1. The Distinction -- Propagation vs. Learning

Dynamic Completion (1035) is the mechanism that propagates improvements. When a fix is found, Dynamic Completion ensures that fix is applied everywhere it applies. This is powerful and necessary.
But propagation answers: where does this fix apply? Learning answers: what does this fix reveal about how we build? These are fundamentally different questions -- and the second question is almost never asked.
A fix without a lesson produces a better platform. A fix with a lesson produces a better way of building platforms. The Learning Loop is what converts individual fixes into durable wisdom.

# 2. The Learning Loop Architecture

The Learning Loop has five components that run in a continuous cycle. It is a Continuous Loop (declared in 0008 as the fourth loop type) -- it runs indefinitely, receiving inputs from every platform operation and accumulating intelligence.

# 3. Learning Loop as Continuous Loop

The Learning Loop is a Continuous Loop (fourth loop type, declared in 0008 Section 14). It does not terminate. It runs in the background of every platform operation, receiving triggers and producing insights.
Cycle Type
What One Cycle Is
Output per Cycle
Trigger cycle
One Learning Trigger fires -- one event is extracted, classified, and entered into the Intelligence Vault
One Intelligence Vault entry at CANDIDATE status
Review cycle
Pattern Report generates -- all CANDIDATE entries from the period are reviewed
Intelligence Vault entries promoted to APPROVED or confirmed as CANDIDATE
Promotion cycle
Governor reviews APPROVED entries -- strongest insights promoted to PROMOTED
Governing principle candidates or protocol additions declared
Enhancement cycle
PROMOTED insights become changes -- new governing principles, new protocol sections, new vocabulary entries
0000 V2, domain protocols, or 1000 updated. Backward propagation of enhancement to all affected elements.
The Learning Loop improves the platform's improvement mechanisms. Dynamic Completion makes the platform better at what it does. The Learning Loop makes Dynamic Completion better at improving the platform. This is the meta-loop -- and it is what makes the platform's growth sustainable rather than additive.

# 6. Default Override Declaration

This Protocol's Override
Fixes are applied and forgotten
Every fix is an Insight Extraction input. The fix is applied AND the lesson is extracted and vaulted.
Learning is informal -- conversations and notes
Learning is structured -- extracted insights have declared formats, confidence levels, promotion paths, and vault entries
Universal patterns are recognized by the team
Universal patterns are detected by the Learning Loop -- evidence from multiple triggering events raises confidence from LOW to HIGH to CONFIRMED

Platform improvements are compounding -- each improvement feeds the Learning Loop, which feeds future improvements. The platform gets better at getting better.

# 7. Audit Mirror

ZERO FINDINGS MANDATORY   Before any Learning Loop extraction -- check the Intelligence Vault for existing insights from the same root cause. Duplicate insights inflate confidence counts without adding evidence quality.
Creation Step
Audit Question
Every document has a Learning Loop slot
Does every suite document show a populated learning_triggers field in its audit mirror section?
Insight Extraction runs on every trigger
Does every gap finding, ZF result, and GPOW phase completion have a corresponding Intelligence Vault entry?
Classification is accurate
Are UNIVERSAL insights actually universal -- tested against multiple domains? Or are domain-specific insights being over-classified?
Promotion cycle runs regularly
Is there evidence of Vault Review at each GPOW phase gate? Are CANDIDATE insights aging without review?
Universal promotions have backward propagation
When an insight is promoted to a governing principle -- did backward propagation run to all documents affected by the new principle?
Anti-patterns declared for all insights
Does every Intelligence Vault entry have a declared anti-pattern (scope boundary)? Principles without boundaries become overfitted rules.
DYNAMIC COMPLETION   The Learning Loop and Dynamic Completion are peers -- not hierarchical. Dynamic Completion propagates fixes. The Learning Loop extracts principles. When the Learning Loop promotes an insight to a governing principle, Dynamic Completion propagates that principle to all suite documents. The two mechanisms together form the platform's evolutionary engine.
