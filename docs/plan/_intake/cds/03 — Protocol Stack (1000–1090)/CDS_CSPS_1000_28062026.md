# 1. Why This Document Exists

The single largest source of misalignment between human intent and AI output is vocabulary. Two parties using the same word to mean different things will produce outputs that diverge from intent -- not because of capability failures, but because the shared reference frame was never established.
Vocabulary alignment is not a nice-to-have preliminary. It is a structural prerequisite. An AI that does not share the human's definition of 'hierarchy' will build hierarchy incorrectly -- every time -- regardless of how well the pipeline is defined.
ZERO FINDINGS MANDATORY   Before using any term from this vocabulary in a pipeline, corespine, page, or element definition -- verify it matches the definition in this document. If your usage differs -- declare the difference explicitly before building.

# 2. The Three-Layer Vocabulary Structure

Every term in this vocabulary is defined at three levels -- matching the three depth levels from Document 0010. An AI consuming vocabulary at Core depth receives the minimum definition needed to use the term correctly. Full depth includes quality criteria, measurement signals, and the hidden principle behind the term.

# 3. CSPS Platform Vocabulary -- Native Terms

These are terms invented within CSPS. They have no industry standard equivalent. Every AI system and every human working within CSPS must use these terms exactly as defined here.
Term
CORE Definition
MEDIUM -- Good / Bad / Measured By
FULL -- Hidden Principle
Corespine
A logical lineage -- the family tree of purpose that an element belongs to, defined by where it comes from and what it owes forward.
Good: every element knows its corespine and the user feels continuity. Bad: elements that look related but belong to different corespines -- the user feels disconnection. Measured by: user context continuity -- can the user articulate where they are and why?
Belonging is felt before it is understood. Corespine membership is the structural source of felt coherence. When corespine is wrong, the user cannot name what is wrong -- they only feel that something is.
Pipeline
A declared sequence of stages that moves a defined need toward a defined resolution -- every stage accountable to the goal, every stage obligated to what follows.
Good: every stage traceable to the goal, no stage existing because it seemed useful. Bad: stages added during build without goal traceability -- orphan stages. Measured by: can every stage answer which goal requirement made it necessary?
A pipeline is an argument. Every stage makes a claim about what is necessary to achieve the goal. A stage that cannot defend its place in the argument does not belong in the pipeline.
Context Backpack
The intrinsic context an element carries as a structural property -- not retrieved, not reconstructed, always present.
Good: element can be consumed at any depth level without external retrieval. Bad: element depends on external documents to explain what it is and why it exists. Measured by: can the element answer all nine questions without referencing anything outside itself?
Context that lives outside the element is context that will be lost. The backpack is the difference between an element that travels with its identity and an element that loses it every time the context window shifts.
Zero Findings
The mandatory discipline of checking what already exists before creating, detecting, or resolving anything new.
Good: every build session begins with confirmed existing state. Bad: starting from scratch without checking -- rebuilding what exists, creating duplicates, missing prior resolutions. Measured by: was the registry checked before this element was defined?
The most expensive thing in platform development is rebuilding what already exists. Zero Findings is the structural practice that makes reuse the default and creation the exception.
Dynamic Completion
The continuous loop that receives every improvement, analyzes where else it applies, and propagates it until every candidate is addressed.
Good: platform elements at end-of-cycle are demonstrably more complete than at start. Bad: improvements stay where they were found -- element 15 at innovation level while elements 1-14 remain at launch level. Measured by: vault entry closure rate and propagation completion percentage.
An improvement that stays local is a missed opportunity for the entire platform. Propagation is not optional -- it is the mechanism that makes investment in quality compound rather than depreciate.
Wiring State
The declared operational status of an element -- one of four levels: Defined, Wired, Reachable, Current.
Good: every element honestly declares its actual wiring state. Bad: elements claiming Current wiring state while their inheritance sources are only Defined. Measured by: does the declared state match the actual inheritance quality?
Existence is not availability. Availability is not actionability. The wiring state is the honest declaration of which of these is actually true -- and honesty about wiring state is the foundation of every reliable execution.
Accumulated Inheritance
The growing chain of context that every stage and element carries forward from all previous stages -- cumulative, not sequential.
Good: every element can show the complete chain and trace each item to its origin. Bad: inheritance assumed to be sequential -- only the immediately preceding stage is checked. Measured by: is every item in the chain traceable to its origin stage?
Inheritance is not a handshake between adjacent stages. It is a growing memory. An element that only remembers its immediate predecessor is an element operating without the context that everything before it established.

# 4. UX/UI Industry Vocabulary -- Three-Layer Definitions

These are standard industry terms. The three-layer definition adds what the standard definition omits -- quality criteria, measurement signals, and the hidden principle that distinguishes competent use from governed use.
Term
CORE Definition
MEDIUM -- Good / Bad / Measured By
FULL -- Hidden Principle
UX (User Experience)
The full spectrum of a person's interaction with a product -- including emotions, perceptions, and outcomes across all touchpoints.
Good: user achieves their goal without friction or confusion. Bad: user achieves the goal but feels frustrated, confused, or mistrustful during the process. Measured by: task completion rate, time on task, and emotional state post-task.
Experience is the residue of interaction. What the user remembers is not what happened -- it is how they felt at the peak moment and the last moment. UX governs both.
UI (User Interface)
The visual and interactive layer through which a user operates a product -- buttons, inputs, layout, typography, color.
Good: UI makes the right action obvious without instruction. Bad: UI requires the user to decode what to do before they can do it. Measured by: first-click accuracy -- does the user click the right thing first?
UI is a conversation conducted without words. Every visual element is a statement. Every missing element is a silence. The quality of the conversation is measured by whether the user understood what was being said.
Hierarchy
The visual and structural priority ordering of elements -- what the eye encounters first, second, third.
Good: primary action is visually dominant, secondary elements recede, the user's eye lands on the correct first action within 3 seconds without instruction. Bad: three or more elements compete equally for attention -- the user scans instead of acts. Measured by: first-fixation point in eye tracking or first-click testing.
Attention is a finite resource. Design must spend it intentionally. Hierarchy is the budget -- and every element that claims attention without earning it is spending the user's attention on the wrong thing.
Flow
The sequence of screens or steps a user moves through to complete a task.
Good: each step feels like the natural next question in a conversation. Bad: the user must re-read, re-enter, or re-orient at any step. Measured by: drop-off rate at each step -- where users leave is where the flow breaks.
A flow is a contract. Each step promises the user that completing it will move them meaningfully forward. A step that breaks that promise -- even once -- breaks the user's trust in every step that follows.
Affordance
A design quality that signals to the user how an element should be used.
Good: the user knows how to interact with an element before touching it -- it looks like what it does. Bad: the element's interaction model is different from what it looks like. Measured by: does the user attempt the correct interaction on first encounter?
Affordance is the design principle that respects the user's prior knowledge. Every element that looks like something familiar invites the user in. Every element that looks like something it is not creates friction before the first interaction begins.
Feedback
Visual, auditory, or haptic signals confirming that a user action was received and processed.
Good: feedback is immediate, specific, and tells the user what happened and what comes next. Bad: silent action -- the user acts and nothing visible changes. Measured by: time from action to visible response -- anything over 100ms requires a loading indicator.
Feedback is the system talking back. Without it, the user is interacting with silence -- and silence in a conversation means the other party did not hear you. Every silent action creates doubt about whether the system received the input.
State
A defined condition of a UI element or screen -- default, hover, active, disabled, error, loading, success.
Good: every state is visually distinct -- the user can immediately identify which state the element is in. Bad: states that look the same -- the user cannot tell if the element is disabled or just unselected. Measured by: can users correctly identify element state in under 1 second?
States are the element's vocabulary. An element that speaks only one state is mute for everything else that happens to it. The user's trust in an element is proportional to how clearly it communicates its current condition.
Cognitive Load
The mental effort required to understand and act on the information presented.
Good: one primary decision per page, supporting context present but not competing, reading flow is natural. Bad: multiple primary decisions competing, excessive information without clear hierarchy. Measured by: number of primary actions visible simultaneously -- more than one is overload.
Every pixel on a page is either helping the user or charging them. Cognitive load is the bill. Good design minimizes the bill while delivering the required information. The goal is not minimalism -- it is economy.
Content Hierarchy
The structured ordering of text and media by importance, guiding the user's attention through the page.
Good: the most important content is encountered first in both visual weight and reading flow. Bad: important content buried beneath secondary content because the secondary content was added first. Measured by: scroll depth to reach primary content -- on mobile, primary content must not require scroll.
Content hierarchy is an editorial decision before it is a design decision. The question is not 'how should this look?' but 'what does the user need to know first, and what is the cost of them knowing it late?'
Accessibility
The design practice of making products usable by people with varying abilities -- per WCAG 2.1 AA standards minimum.
Good: all interactive elements reachable by keyboard, all text at 4.5:1 contrast ratio minimum, all images have meaningful alt text. Bad: interactive elements only reachable by mouse, low contrast, images without alt text. Measured by: WCAG 2.1 AA automated scan plus manual keyboard navigation test.
Accessibility is not a feature for some users. It is a quality standard for all users. Designs that pass accessibility criteria are more usable for everyone -- higher contrast is easier to read in sunlight, keyboard navigation is faster for power users, clear labels help users with any level of familiarity.

# 5. Vocabulary Governance Rules

Rule
Definition
Enforcement
No synonym drift
Every term in this vocabulary has one definition. Synonyms are not permitted within platform documentation. If two terms mean the same thing, one is deprecated.
Any document using a term in a way that diverges from this vocabulary must declare the divergence explicitly before the first use.
Native terms take precedence
CSPS native terms (Section 3) override any industry usage that conflicts. If an industry term means something different in CSPS context -- the CSPS definition applies.
All AI sessions are given this vocabulary document before any protocol document. Vocabulary is the foundation that all other language builds on.
Three-layer consumption
AI builders consume vocabulary at the depth level appropriate to their session type. Core for mechanical tasks, Full for governance sessions.
Depth Router (3010) includes vocabulary depth in session bundle assembly.
Vocabulary expansion is governed
New terms require a vault entry, a three-layer definition, and Platform Governor approval before they become active vocabulary.
The Vocabulary Registry tracks all active terms, their approval date, and their current build depth.
DYNAMIC COMPLETION   Every vocabulary improvement -- a refined hidden principle, a better quality measurement, a new native term -- is a vault entry. Vocabulary improvements propagate to all documents that use the affected term and to all AI sessions that have consumed the previous definition.
