The Pipeline Protocol is the first executable layer of the CSPS UX/UI Suite. It transforms a locked goal into a governed sequence of stages -- each with declared relationships, accumulated inheritance, and explicit obligations forward.

# 2. What a Pipeline Is -- and Is Not


## 2.1 Definition

A pipeline is a declared sequence of stages, each with a specific role, that together move a defined need toward a defined resolution. Every stage is accountable to the goal above it and obligated to what comes after it.
Every stage has a named relationship with what precedes it and what follows it. These relationships are not implied -- they are declared explicitly and carry accumulated inheritance forward at every step.
Nothing in a pipeline exists because it seemed useful. Everything exists because the goal required it.
This principle applies not only to the pipeline as a whole -- it applies to every stage, every element, every transition, and every page the pipeline touches.

## 2.2 What a Pipeline Is NOT

A flowchart or user journey map
A feature list organized by screen
A process that starts with UI and works backward
A sequence where stages exist because they seemed logical in the moment
DEFAULT OVERRIDE:   These are the AI default gravity patterns. This protocol explicitly overrides all of them.

# 3. Goal Definition -- The Entry Gate

The pipeline cannot exist without a locked goal. Goal Definition is not a one-time exercise at the pipeline opening. It is a mandatory layer that propagates downward -- every stage, every element, and every page must be traceable back to this goal.
If the trace from any element back to the goal breaks, existence is not justified.

## 3.1 The Five Questions -- In Intuitive Order

The questions follow natural human reasoning: start with the felt need, understand the context, declare the constraints, map the corespines, confirm the outcome. Outcome is always near the end -- because outcome is what the entire sequence earns.
Q1 -- What is the need or wish that makes this pipeline necessary?
Start here. Not with the solution. Not with the feature. With the felt need -- the reason someone would want this pipeline to exist at all.
Quality
Example
Good
Users arrive without enough context for the system to serve them meaningfully. There is a need to collect that context in a way that feels natural and builds trust.
Bad
We need an onboarding flow.
The test: does this statement describe a real human or system need -- or does it describe a solution that was already decided?
Q2 -- Who arrives at the start of this pipeline and in what state?
What does the user know, have, and expect at the moment they enter? What context do they carry in? What has accumulated before this pipeline begins?
This defines the inherited entry state -- the sum of everything that exists before Stage 1. Without it, the pipeline opens into a vacuum. The first stage has nothing to inherit and the accumulated chain cannot start.
Q3 -- Which corespines does this pipeline touch?
A pipeline is goal-directed. It will cross multiple corespines. These must be declared before any stage is defined -- not discovered mid-build. Each corespine crossing is a transition point that requires explicit handling.
Undeclared corespine crossings are the source of most disconnection -- in UX, in logic, and in inherited context.
Q4 -- What are the constraints and boundaries of this pipeline?
What must this pipeline never do? What is explicitly out of scope? What generic default behaviors must be overridden?
Constraints are declared before the outcome -- because they shape the path. An outcome defined without constraints produces a pipeline that achieves the goal through means that violate governing principles.
Q5 -- What is the observable signal that this pipeline is complete?
This is the outcome. It appears here -- near the end -- because it is what the entire sequence earns.
Not 'the user finished.' Not 'the form was submitted.' What specifically changed -- in state, in data, in system behavior, in the user's situation -- that confirms the goal defined in Q1 was achieved?
This signal becomes the audit target for the entire pipeline. Every stage is evaluated against its contribution to producing this signal.

# 4. Stage Definition

Once the goal is locked, the pipeline is broken into stages. Each stage is a unit of progress toward the resolution. Every stage knows what came before it, what it carries forward, and what comes after it.

## 4.2 The Relationship Declaration -- Both Directions

Every stage must explicitly state its relationships in both directions. This is not documentation -- it is the wiring.
Direction
Declaration Format
Backward
I follow [Stage Name]. I receive from it [specific inherited content]. My accumulated inheritance chain now contains [full cumulative list].
Forward
I precede [Stage Name]. I hand to it [specific content]. This becomes part of its accumulated inheritance.
If a stage cannot complete both declarations, it is not ready to be built.

## 4.3 Accumulated Inheritance -- The Governing Rule

Inheritance is not a handshake between adjacent stages. It is a growing chain.
By Stage 4, that stage carries everything passed from Stage 1, Stage 2, and Stage 3 -- plus what it received from the entry state defined in Section 3 Q2. Nothing drops out of the chain unless explicitly declared as resolved or consumed.
If something drops without declaration, that is Gap Type 2 -- an inheritance break. It must be detected and resolved before implementation proceeds.
The accumulated inheritance slot is the full chain at that point. It grows with every stage. This is what makes the pipeline coherent as complexity scales -- not repetition, not re-prompting, but the chain carried forward structurally within every stage that touches it.

## 4.4 Stage Types -- Four Only

Type
What It Does
Backward Relationship
Forward Obligation
Critical Rule
Collection
Receives something from the user or system -- input, selection, upload, confirmation, authentication.
Receives the context that makes this collection meaningful.
Passes the collected item -- validated -- into the accumulated chain.
What is collected must be validated before being passed forward. Unvalidated collection poisons the chain.
Decision
Evaluates a condition and routes accordingly -- branch logic, eligibility checks, state assessments.
Receives the accumulated chain and evaluates against it.
Passes the full chain -- plus the decision outcome -- down every declared branch.
Every branch must be declared. No implicit defaults. An undeclared branch is a live wire.
Transition
Moves between corespines -- the handoff point.
Receives the full accumulated chain from the departing corespine.
Carries the chain -- translated into the receiving corespine's context -- forward.
The receiving corespine must be declared. Most failure-prone stage type because most frequently skipped.
Resolution
Produces the declared outcome.
Receives the complete accumulated chain -- everything the pipeline built.
Produces the observable signal defined in Q5. Nothing else.
This is the ONLY stage permitted to be terminal. And only if it produces the resolution signal.

# 5. Gap Detection -- Three Passes, Six Types

Gap detection is not a review -- it is a gate. Each pass must be clean before the pipeline proceeds to the next protocol layer.

## 5.1 The Six Gap Types

Gap Type
Name
What It Is
Detection Question
Resolution
1
Orphan Stage
A stage exists but cannot be traced to a goal requirement.
Which sentence in Section 3 made this stage necessary?
Trace to goal or remove.
2
Inheritance Break
A stage's accumulated inheritance is incomplete -- something dropped without declaration.
Is the full chain present and accounted for?
Restore the missing inheritance or explicitly declare it consumed.
3
Undeclared Transition
The pipeline crosses a corespine boundary without a declared Transition Stage.
Does every corespine in Q3 have a corresponding Transition Stage?
Insert explicit Transition Stage with full backpack.
4
Unresolved Branch
A Decision Stage has a branch with no declared destination.
Does every branch lead to a declared stage?
Define destination or explicitly declare branch as out of scope.
5
Missing Resolution Signal
The pipeline ends without a stage producing the observable signal from Q5.
Which stage produces the exact signal defined in Q5?
Add Resolution Stage or redefine the goal.
6
Wiring State Mismatch
A stage declares itself Current but its accumulated inheritance contains items that are only Defined.
Is every item in the accumulated chain at the same wiring state as the consuming stage?
Escalate the lagging item's wiring state or declare the dependency explicitly.
