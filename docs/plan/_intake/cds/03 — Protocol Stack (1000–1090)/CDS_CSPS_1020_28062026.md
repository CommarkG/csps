# 2. What a Corespine Is -- and Is Not


## 2.1 Definition

A corespine is a logical lineage. It is the family tree of purpose that an element belongs to -- defined by where it comes from, what logic or goal created the need for it, and what it owes to the elements that come after it within the same lineage.
A corespine is not a visual grouping. It is not a page section. It is not a feature category. It is a lineage of purpose -- and every element either belongs to one or does not belong in the system.
The pipeline is goal-directed -- it moves from need to resolution in a declared sequence. The corespine is lineage-directed -- it defines which logical family each stage and element belongs to, regardless of where that stage appears in the pipeline sequence.
A single pipeline will cross multiple corespines. This is expected and correct. What must be governed is how those crossings happen.

## 2.2 The Two Questions Every Corespine Answers

Question
What It Establishes
Why It Matters
Where do I come from?
The root goal, decision, or system need that created this lineage.
Without a declared origin, the corespine is floating. Floating lineages produce elements with no accountability.
What do I owe forward?
The obligations this corespine carries to elements downstream within the same lineage.
Without declared obligations, the corespine terminates arbitrarily. Arbitrary termination breaks the pipeline's accumulated inheritance chain.

## 2.3 The Critical Distinction -- Pipeline vs. Corespine

Dimension

Corespine
Direction
Goal-directed -- moves from need to resolution
Lineage-directed -- defines family membership

GOVERNING RULE:   Both must be honored simultaneously. An element that knows its pipeline position but not its corespine membership is structurally incomplete. An element that knows its corespine but not its pipeline position is ungoverned at execution.

# 3. Corespine Anatomy -- The Three Layers

Every corespine has three structural layers. All three must be defined before the corespine is considered Wired.

## 3.1 The Root

The root is the originating purpose of the corespine -- the goal, decision, or system need that created the lineage. Every element in the corespine must be traceable back to this root.
Root Element
Must Declare
Root Goal
The single need or decision that made this corespine necessary. Traceable to Pipeline Protocol Section 3 Q1.
Root Owner
Which pipeline stage or system decision initiated this corespine.
Root Scope
What this corespine governs -- and explicitly what it does not govern. Boundaries prevent corespine sprawl.
Root Wiring State
Defined / Wired / Reachable / Current. The root's wiring state sets the ceiling for all elements within it.

## 3.2 The Trunk

The trunk is the main sequence of the corespine -- the stages and elements that carry the root's purpose forward. The trunk is where accumulated inheritance travels.
Trunk Element
Must Declare
Trunk Stages
Each stage in sequence, with pipeline position declared alongside corespine position.
Inheritance Flow
What each trunk stage receives from the stage before it and adds to the accumulated chain.
Branch Points
Where the corespine splits into sub-lineages. Every branch point must be declared explicitly.
Transition Points
Where the trunk hands off to another corespine. Must be handled by a Pipeline Transition Stage.

## 3.3 The Branches

Branches are sub-lineages that emerge from the trunk. Each branch inherits from the trunk but serves a more specific purpose within the same root goal.
Branch Element
Must Declare
Branch Origin
Which trunk stage this branch emerges from and why.
Branch Purpose
The specific sub-goal this branch serves within the root goal.
Inherited Context
The accumulated inheritance from the trunk that this branch carries in.
Branch Resolution
What this branch produces and where it rejoins the trunk -- or whether it terminates independently.
Branch Wiring State
Branches inherit the trunk's wiring state ceiling. A branch cannot be Current if the trunk is only Defined.

# 5. Corespine Crossing Protocol

A corespine crossing is the moment a pipeline moves from one corespine's governance to another's. This is the most failure-prone point in any pipeline -- and the most frequently skipped in AI-generated flows.
Every corespine crossing must be handled by an explicit Pipeline Transition Stage. A crossing without a Transition Stage is Gap Type 3 -- and blocks progression to Page Distribution.

## 5.1 What Makes a Crossing Explicit

Requirement
What It Means in Practice
Declared in Pipeline Q3
The crossing was named before any stage was defined. Not discovered mid-build.
Transition Stage exists
A dedicated Pipeline Transition Stage sits at the crossing point in the pipeline sequence.
Inheritance translated
The accumulated inheritance from the departing corespine is explicitly translated into the receiving corespine's context. Not assumed to transfer automatically.
User experience bridged
The crossing produces a felt continuity for the user -- not a context jump. The user never feels 'wait, where am I?'
Both corespine backpacks updated
The departing corespine's Forward Obligation slot and the receiving corespine's Accumulated Inheritance slot both reference this crossing.

## 5.2 The Inheritance Translation Requirement

This is the most critical and most skipped step in corespine crossings.
Accumulated inheritance does not automatically transfer between corespines. Each corespine has its own context model -- its own vocabulary, its own data structures, its own obligations. What the departing corespine accumulated must be actively translated into terms the receiving corespine can consume.
Translation Element
What Must Be Declared
What transfers
Specific items from the accumulated inheritance chain that the receiving corespine needs.
What transforms
Items that transfer but must be reframed in the receiving corespine's context model.
What terminates
Items from the accumulated chain that are consumed at this crossing and do not continue forward.
What is new
Context that the receiving corespine introduces fresh -- not inherited from the departing corespine.

## 5.3 The User Experience of a Crossing

A user cannot see corespine boundaries. But they feel them -- as either continuity or disconnection.
Experience Signal
What It Indicates
'This makes sense -- I know where I am'
Crossing is explicit. Inheritance was translated. The bridge was built.
'Wait, where am I? What happened to what I just did?'
Crossing is implicit. Inheritance was dropped. Gap Type 3 is present.
'Why is it asking me this again?'
Inheritance break at the crossing. Accumulated context was not translated forward.
'This feels like a different product'
Transition Stage missing. The user experienced a raw corespine boundary with no bridge.
Belonging is felt before it is understood. The job of the Transition Stage is to make belonging invisible and disorientation impossible.

# 6. The Corespine Map -- Format and Validation


## 6.1 What the Map Contains

The Corespine Map is the output of this protocol. It is a structured declaration -- not a visual diagram -- that is consumed by the Gap Detection Protocol (1030) and the Page Distribution Protocol (1040).
Map Element
Content
Corespine Registry
All corespines in this pipeline, each with a unique ID, name, and type.
Lineage Tree
The hierarchical relationship between corespines -- which are roots, which are trunks, which are branches.
Crossing Registry
Every declared crossing point, with the corresponding Pipeline Transition Stage ID and inheritance translation declaration.
Wiring State Summary
The current wiring state of every corespine and its ceiling effect on dependent elements.
Branch Registry
All declared branches, their origin trunk stages, and their resolution or termination points.
Gap Detection Pre-check
Preliminary check against Gap Type 3 -- are all crossings declared in Pipeline Q3 matched to Transition Stages?

## 6.2 Validation Gates

The Corespine Map must pass two validation gates before it is considered complete:
Gate
Condition
Blocks
Gate 1 -- Completeness
Every corespine declared in Pipeline Q3 has a populated backpack and appears in the map.
Map cannot be submitted to Gap Detection until Gate 1 is clean.
Gate 2 -- Crossing Coverage
Every corespine crossing has a corresponding Pipeline Transition Stage. Zero undeclared crossings.
Gap Detection Pass 2 cannot run until Gate 2 is clean.
