# 1. Position in the System

When this runs:  After Gap Detection Pass 3 is clean. The Page Map is complete and all page backpacks are populated.
What it receives:  A complete Page Map with validated page assignments, page backpacks, and page-to-page handoff declarations.
What it produces:  Every UI element on every page fully defined -- with a populated backpack, nine-question protocol answers, depth declarations, and context weight assigned.
This is the protocol where abstract pipeline logic becomes concrete UI elements. A pipeline stage on a page is still an abstraction. An element is the smallest unit of user interaction -- a title, a button, a text field, a progress indicator, a card. This protocol governs how every element earns its place.
ZERO FINDINGS MANDATORY   Before defining any element -- check the Element Registry. Does this element type already exist in the system with a validated definition? A button defined once with a complete backpack is the button used everywhere. Elements are never redefined from scratch when a validated definition already exists.

# 2. The Nine-Question Protocol

Every element must answer all nine questions before it is placed on a page. These questions are not documentation requirements -- they are the element's definition. An element that cannot answer all nine does not yet exist as a governed element. It is a placeholder.
An element that exists visually but cannot answer the nine questions is ungoverned. An ungoverned element is a liability -- it cannot be audited, cannot be orchestrated at the correct depth, and cannot be trusted to carry the right context forward.
Q1 -- What is the need that made me necessary?
Not what the element is. The felt need -- from the pipeline goal and the page goal -- that created the requirement for this element to exist. If this question cannot be answered, the element does not belong on this page.
Q2 -- Why am I here and not absent?
What breaks if this element is removed? This is the justification gate. If nothing significant breaks, the element should not exist. Decorative elements that serve no pipeline function do not pass Q2.
Passing Q2 is the entry requirement for existence. Every element earns its place or does not have one.
Q3 -- Where do I come from?
Which corespine do I belong to? Which pipeline stage placed me on this page? Which goal requirement upstream is responsible for my existence? This is the accountability anchor. The element does not decide what it is -- the corespine and pipeline already decided. The element is the expression of that decision.
Q4 -- What did I inherit?
What context, data, or state arrived with me from all previous stages and pages? An element that inherits nothing is either the start of a new pipeline -- which must be declared explicitly -- or it is disconnected, which is a gap.
ZERO FINDINGS MANDATORY   Before declaring inheritance -- check what the previous page declared in its Forward Obligation slot. The element's inherited context must match what was passed. If there is a discrepancy, it is an inheritance break -- Gap Type 2 -- and must be resolved before the element is placed.
Q5 -- What do I trigger forward?
What does acting on this element produce? What changes in state, data, or flow? What does the next element or page receive because of me? Every element is a handoff point. No element is permitted to be a dead end unless the pipeline explicitly declares it as a terminal Resolution element.
Q6 -- What makes me clear to the user?
Not beautiful -- clear. Can the user identify my purpose without instruction? Does my label describe what I do, not what I am? Is my affordance honest -- do I look like what I actually am? Clarity is assessed before aesthetics. Always.

Q7 -- What are my performance variants?

Q8 -- What is my context weight in this specific situation?
Context is more significant than content. The same element carries different weight depending on where it sits, what it inherited, and what it is serving. Weight is situational -- not fixed.
A title on a welcome page and a title on an error state page are not the same element. The orchestrator determines context weight by evaluating: which page type contains this element, which pipeline stage it serves, what the user's state is at this moment, and what the accumulated inheritance indicates about urgency and priority.

Q9 -- According to what am I defined this way?
The accountability question. Every element must reference: the corespine rule that placed it, the pipeline stage it serves, the page type standard it inherits from, and the variant decision that determined its weight. This is the definition trail. It prevents drift. It prevents AI freestyle. Every element can be audited -- why are you this way? -- and the answer exists in the structure.
According to what am I defined this way? is the question that closes the AI freestyle loop. An element that cannot answer it is not governed. An element that can answer it cannot be overridden by default AI behavior -- because the definition is stronger than the default.

# 5. The Element Registry

Every element defined using this protocol is registered in the Element Registry. The registry is the platform's element memory -- it prevents redundant definition, enables reuse, and is the Zero Findings check target for all future element definitions.
ZERO FINDINGS MANDATORY   The Element Registry must be consulted before every new element definition. An element type that already exists in the registry must be inherited -- not redefined. A new registry entry requires explicit justification that no existing entry covers this element's role.

# 6. Default Override Declaration

AI Default
This Protocol's Override
Elements are placed where they look right
Every element passes nine questions before placement. Position is derived from pipeline stage and corespine membership.
Labels describe what elements are
Labels describe what elements do or produce. 'Submit' is never acceptable. 'Save and continue to review' is.
Context weight is a visual decision
Context weight is determined by pipeline position, page type, user state, and accumulated inheritance -- not by visual preference.
Element states are added during development
All states are declared in the element backpack before build. An element with undeclared states is incomplete.
Elements are defined per project
Elements are defined once in the registry and inherited everywhere they apply. Redundant definition is a structural error.
Variants are style options
Variants are orchestrator-assigned based on context weight. The element does not choose its variant.
