# 1. Position in the System

When this runs:  Last. After every protocol from 0000 through 1060 is complete and validated. UI Expression is what everything above it earns.
What it receives:  Validated page templates with complete element registries, context weights assigned, variants declared, all backpacks populated.
What it produces:  Visual decisions -- color, typography, spacing, emphasis, density, CTA styling, state expressions -- each derived from a structural decision already made in the protocol stack above.
UI Expression is the last layer -- and deliberately so. Every visual decision in this protocol is derived from a structural decision that was already made. Nothing is invented here. Everything is expressed.
A visual decision without a structural derivation is decoration. Decoration is not governed. This protocol produces zero decoration -- only expression of what the structure already determined.
ZERO FINDINGS MANDATORY   Before making any visual decision -- check whether an equivalent decision already exists in the Design Token Registry or a previous UI Expression session. Visual consistency across the platform depends on reusing validated decisions, not reinventing them.

# 2. The Derivation Principle

Every visual decision in this protocol is answerable by one question: what structural decision above this layer made this visual decision necessary and correct?
Visual Decision
Structural Source
Derivation Logic
What is emphasized
Element context weight from 1050 Q8
Hero weight = maximum visual emphasis. Compact weight = visual recession. The structure decided emphasis. UI expresses it.
What is the CTA
Pipeline stage Forward Obligation from 1010
The primary pipeline action is always the CTA. It inherits Hero variant from 1050. Visual treatment follows.
Is the page overloaded
Pipeline stages assigned to page from 1040
Count the primary pipeline actions on this page. More than one = overloaded by definition. Not a visual judgment.
What color signals action
Element type from 1050
Action elements carry the primary action color. Display elements carry neutral. Error elements carry error color. Type determines color -- not preference.
What size is the title
Page type and pipeline position from 1040 and 1060
Entry page title = largest. Collection page title = standard. The page type determined size before any design decision was made.
How much whitespace
Cognitive load profile from 1040 page type
High cognitive load pages get more whitespace -- the load profile determined density before layout began.
What is minimalist vs rich
Cognitive weight of the pipeline moment from 1010
Resolution and Transition stages get minimal visual load. Collection stages get structured richness. The pipeline moment determines visual density.

# 3. The Visual Decision Framework

Six categories of visual decision. Each category has a derivation source, a decision rule, and a quality test. No visual decision is made outside these categories without explicit justification and vault entry.

## 3.1 Emphasis & Hierarchy

What the eye sees first, second, and third on every page is determined by element context weight -- not by visual instinct.
Context Weight
Visual Treatment
Quality Test
Hero
Maximum size, maximum contrast, maximum visual authority. One per page -- always.
Cover the primary element. Can the user still identify the primary action? If yes -- it is not Hero enough.
Standard
Moderate size, clear but not dominant. Readable without demanding.
Does Standard element compete with Hero? If yes -- reduce Standard.
Compact
Small, present, clearly available but visually receding.
Is Compact element visible without searching? If it requires search -- it is too small.
Minimal
Barely present. Available on demand. Never soliciting.
Does Minimal element draw the eye? If yes -- it is not Minimal enough.
One Hero per page. This is not a design preference. It is a structural rule derived from the pipeline stage assignment. One page -- one primary pipeline action -- one Hero element.

## 3.4 Spacing & Density

Spacing is determined by cognitive load profile. High cognitive load pages need more space between elements -- because the user is processing more. Low cognitive load pages can be denser -- because the user's attention is not split.
Cognitive Load Profile
Spacing Rule
Page Types
Maximum load -- multiple decisions required
Maximum whitespace. Elements breathe. No visual crowding.
Decision pages, complex Collection pages
Standard load -- one primary action
Standard spacing. Clear separation between primary and secondary elements.
Collection pages, Progress pages
Low load -- orient and confirm
Compact spacing permitted. Information density can increase.
Transition pages, Resolution pages
Display load -- aggregate view
Grid-based density with clear visual hierarchy. Whitespace used structurally, not generously.

## 3.5 State Expression

Every element state declared in the Element Definition Protocol (1050) must have a visual expression. States are not added during development -- they are designed here, derived from the state declarations already made.
State
Visual Expression Rule
Quality Test
Default
The element at rest. No visual noise. Clearly available.
Is the element's purpose clear before any interaction?
Hover
Subtle visual shift -- color lightens, shadow appears, cursor changes. Affordance confirmed.
Does hover feel responsive without being jarring?
Active / Focus
Clear visual selection. Color intensifies. Border appears. Keyboard focus ring always visible.
Is active state visible to keyboard-only users? WCAG AA required.
Loading
Motion that indicates progress -- not spinner by default. Progress bar preferred for pipeline actions.
Does loading state reassure or anxiety-provoke? Test with 3-second delay minimum.
Success
Positive color. Checkmark or equivalent. Brief -- the pipeline moves on.
Does success state overstay? It should dismiss within 2 seconds unless the user is on a Resolution page.
Error
Error color. Clear message. Recovery action visible immediately. Never just red.
Can the user recover from this error without leaving the page? If not -- the error state is incomplete.
Disabled
Visually receded. Not hidden -- present but clearly unavailable.
Does the user understand why this element is disabled? If not -- add a tooltip at Minimal weight.

## 3.6 Overload Detection

A page is overloaded when its visual expression asks the user to process more than one primary action simultaneously. Overload detection is structural -- derived from the pipeline stage count -- but expressed visually.
Overload Signal
Visual Indicator
Resolution
Two or more Hero-weight elements competing
Both elements draw the eye equally -- neither wins
Return to 1040. The pipeline stages on this page must be split across two pages.
More than five Standard-weight elements visible simultaneously
The page feels busy -- the user scans rather than acts
Convert secondary Standard elements to Compact. If still busy -- return to 1040.
CTA not immediately identifiable without scanning
The user's eye wanders before finding the primary action
Increase Hero element contrast. Reduce all other elements by one variant level.
Error state competes with primary action
Both error and CTA are demanding attention simultaneously
Error takes temporary Hero status. Primary CTA becomes Standard until error is resolved.

# 4. The Design Token Registry

Every visual decision made in this protocol produces a design token -- a named, reusable variable that carries the decision forward into implementation. Tokens are not CSS variables. They are governed decisions with derivation trails.
ZERO FINDINGS MANDATORY   Before creating any new token -- check the Design Token Registry. A token for this visual decision may already exist. Creating a duplicate token for the same semantic role is a structural error equivalent to defining a duplicate element type.
Token Category
Examples
Derivation Source
Registry Rule

Color System Section 3.2
One token per semantic role. No two tokens for the same role.
Typography tokens
type-display, type-heading-1, type-body-standard
Typography Scale Section 3.3
One token per typography level. Scale is fixed -- tokens do not proliferate.
Spacing tokens
space-loose, space-standard, space-compact
Cognitive load profiles Section 3.4
Three spacing levels only -- matching the three cognitive load profiles.
Shadow tokens
shadow-hero, shadow-standard, shadow-flat

Shadows signal elevation -- elevation signals context weight. Four levels maximum.
Motion tokens
motion-feedback, motion-transition, motion-loading

Motion is semantic -- each token has a declared purpose. Decorative motion has no token.
Border tokens
border-interactive, border-container, border-error

Borders signal interactivity or grouping -- never decoration.
