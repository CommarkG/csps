# 1. Purpose

Role:  The first wizard in the CSPS build sequence. The human cannot define a pipeline until this wizard produces a locked, validated goal.
Output:  A locked goal object -- containing all five question answers, a single outcome sentence, and the entry state declaration -- ready for consumption by the Pipeline Builder Wizard (2010).
The Goal Definition Wizard is not a form. It is a structured conversation that surfaces the real goal beneath the stated goal. Most stated goals are solutions. The wizard works backwards from the stated solution to the underlying need -- then forwards from the need to a testable outcome.
The wizard never accepts the first answer. It probes. It challenges. It asks what would break if this goal were not achieved. It asks who feels the need and when. It does not move forward until the goal is stated as a felt need with an observable resolution signal.

# 3. The Anti-Triviality Rules

The wizard enforces three rules that prevent shallow goal definitions -- the kind that look complete but produce ungoverned pipelines.
Rule
What It Prevents
How Wizard Enforces It
No solution-first goals
Goals stated as features ('I want a dashboard') rather than needs ('Users cannot see their progress')
Wizard restates every solution-first goal as a need and asks for confirmation before proceeding.
No unmeasurable resolution signals
Resolution signals that cannot be verified ('Users feel better')
Wizard requires the human to state what will be observable or measurable -- not felt.
No unconstrained scope
Goals with no declared boundaries that expand indefinitely during build
Wizard requires at least one explicit constraint and one out-of-scope declaration before locking.
ZERO FINDINGS MANDATORY   Before Step 1 -- check whether a similar goal has been defined in a previous session. A goal that already exists in locked form may only need refinement -- not full redefinition. Wizard presents matching existing goals for review before starting fresh.
DYNAMIC COMPLETION   Every locked goal object is a vault entry. The vault tracks goal patterns -- recurring goal types, recurring constraint patterns, recurring resolution signal formats. These patterns improve the wizard's probing questions over time.
