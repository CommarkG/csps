# 1. Purpose

Input:  Complete Page Map from Page Distributor (2040).
Output:  Every element on every page fully configured -- nine questions answered, backpack populated, variant assigned, context weight declared, Element Registry updated.
The Element Configurator Wizard is where abstract page structure becomes concrete UI elements. It enforces the Element Definition Protocol (1050) -- ensuring every element passes all nine questions before placement, every element's context weight is derived from structural factors, and the Element Registry is updated with every new definition.

# 2. Wizard Flow

Step
Wizard Action
Gate
1 -- Load page map and template
For each page -- load the page backpack and the associated page template from 1060. Display recurring elements that are pre-defined.
Human confirms template is correct for this page type. Recurring elements are not reconfigured -- they are inherited.
2 -- Zero Findings on element registry
Before defining any element -- check Element Registry for existing definitions that match the required element type and pipeline position.
Human confirms which existing definitions can be inherited. New definitions are created only when no match exists.
3 -- Apply nine-question protocol
For each non-recurring element -- wizard guides the human through all nine questions in order. Questions are mandatory. Skipping is not permitted.
All nine questions answered. Wizard validates Q2 (justification) and Q9 (definition trail) before proceeding.
4 -- Assign variants and context weight
Wizard derives context weight from four factors (page type, pipeline stage, user state, inheritance chain). Proposes variant. Human confirms.
Variant is confirmed -- not invented. If human disagrees, wizard shows the structural derivation and requires an override with documented reason.
5 -- Declare all states
For each element -- wizard presents the six mandatory states and asks for visual expression intent for each.
All six states declared. Error state must include recovery action -- no error state is accepted without one.
6 -- Update element registry
Every new element definition is registered. Existing definitions that were inherited are flagged with incremented reuse count.
Registry updated before export.
7 -- Export to UI Expression Engine
All element definitions exported to 2060. Vault entry created for any new element types.
Human confirms export.
The wizard blocks any element that cannot pass Q2. An element that has no answer to 'what breaks if I am absent' does not exist in a governed system. No exceptions.
DYNAMIC COMPLETION   Every new element definition is a propagation candidate. A new element type that solves a problem on one page likely applies to all pages in the same pipeline stage type. Vault entry triggers analysis.
