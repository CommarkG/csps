# 1. Purpose

Input:  Fully configured elements from Element Configurator (2050).
Output:  Complete visual decision set -- color assignments, typography levels, spacing profiles, state expressions, design tokens -- all derived from structural decisions already made. Design Token Registry updated.
The UI Expression Engine Wizard is the final wizard in the build sequence. It receives fully governed elements and derives their visual expression. Nothing is invented here -- everything is derived. The wizard enforces the UI Expression Protocol (1070) at every step, ensuring every visual decision is traceable to a structural source.

# 2. Wizard Flow

Step
Wizard Action
Gate
1 -- Zero Findings on token registry
Check Design Token Registry for existing tokens that cover each required visual decision. Present existing tokens for reuse.
Human confirms which tokens apply. New tokens created only when no existing token covers the semantic role.
2 -- Derive emphasis hierarchy
For each page -- wizard reads context weights from element backpacks and derives the visual emphasis hierarchy. Identifies the Hero element.
Exactly one Hero element per page confirmed. If more than one -- wizard blocks and returns to 2050.
3 -- Assign color tokens
For each element -- wizard assigns color token based on element type and state. Semantic color roles are fixed.
All color assignments traceable to semantic role. No color assigned by preference.
4 -- Assign typography tokens
For each element -- wizard assigns typography level based on element variant and page type.
All typography levels traceable to variant and page type derivation.
5 -- Apply spacing profiles
For each page -- wizard applies spacing profile based on cognitive load profile from 1040.
Spacing profile matches page type cognitive load. No custom spacing without structural justification.
6 -- Express all states
For each element -- wizard produces visual expression for all six declared states.
All states expressed. Error state expression includes visible recovery action.
7 -- Overload detection
Wizard runs overload detection on every page -- checks four overload signals.
All overload signals clean. Any violation returned to 2050 or 2040 for structural resolution.
8 -- Update token registry and export
New tokens registered. Complete visual decision set exported. Vault entries created for new tokens.
Human confirms export. Build sequence complete.
Any visual decision that cannot be traced to a structural source is rejected by the wizard. The human is asked to identify the structural basis -- not to justify the visual preference.
When the UI Expression Engine completes, the full build sequence is done. The output is a governed, traceable, auditable set of visual decisions derived from the goal the human stated in the Goal Definition Wizard (2000). Every decision between those two points is documented, validated, and registered.
DYNAMIC COMPLETION   Every new design token is a propagation candidate. A token created for one pipeline may apply to all pipelines using elements in the same semantic role. Vault entry triggers analysis across the entire platform.
