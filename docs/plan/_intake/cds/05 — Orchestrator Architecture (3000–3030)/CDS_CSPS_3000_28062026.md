# 1. Purpose & Position

Role:  The central coordination mechanism of the CSPS platform. The orchestrator receives execution requests, reads element registries, selects depth levels, bundles context, and coordinates all pipeline and wizard executions.
Relationship to wizards:  Wizards are human-facing guided sessions. The orchestrator is the machine-facing execution layer. When a wizard completes, the orchestrator receives its output and coordinates what happens next.
Relationship to protocols:  Every protocol in the 1000-series defines rules. The orchestrator enforces those rules at execution time -- not as documentation but as operational constraints.
The orchestrator is the mechanism that makes the platform self-governing. Without it, every protocol, every backpack, every registry is documentation. With it, the documentation becomes executable governance -- running in every session, enforcing every rule, selecting every depth level, and feeding every finding back to Dynamic Completion.
The orchestrator never guesses. It reads declared structures. If a structure is missing, it does not fill the gap with a default -- it declares the gap and halts until the gap is resolved or declared as a known constraint.

# 2. Core Engine Responsibilities

Responsibility
What the Engine Does
What Happens If It Fails
Session intake
Receives every execution request. Classifies it by type: build session, governance session, audit session, propagation session, fast mechanical task.
Unclassified sessions default to Medium depth -- never Full, never Core. Unclassified sessions are flagged for review.
Context assembly
Reads the element registry, pipeline registry, corespine map, and template registry to assemble the execution context for the session.
Missing registry entries halt the session. The orchestrator does not proceed with incomplete context.
Depth selection
Calls the Depth Router (3010) to determine the correct depth level for each element in the session.
If depth cannot be determined, element is consumed at Core depth and flagged for Depth Router review.
Bundle assembly
Calls the Bundling Engine (3020) to assemble the minimum sufficient context bundle for the session.
Oversized bundles are flagged. Undersized bundles that miss required context halt the session.
Execution coordination
Coordinates the execution sequence -- which wizard or protocol runs first, what its output feeds, what gates must be passed.
Out-of-sequence execution is blocked. Gates are enforced -- not advisory.
Gap monitoring
Monitors every execution for gap signals -- inheritance breaks, wiring state mismatches, orphan elements. Feeds findings to Gap Detection Engine (2030) and Dynamic Completion vault.
Gap signals that are not captured are the most dangerous failure mode. All session outputs are scanned before handoff.
Audit trail
Records every decision made during the session -- depth selection, bundle composition, gate status, gap findings.
Sessions without audit trails cannot be audited. Every session produces a trail or is flagged as incomplete.
