## Section 2 -- Critical Vocabulary

Every term below is platform-specific. Do not interpret using general software development vocabulary.

CORESPINE: A governed lineage of purpose. A trunk with branches and sub-branches that declare what a platform does, how it governs itself, and what rules apply at every level. NOT a pipeline. NOT a framework. A corespine is the backbone from which everything inherits.

PIPELINE: A declared sequence of stages that uses segments of one or more ratified corespines. Inheritance and dependencies are hardwired and mechanically enforced. A pipeline is NOT a corespine in motion -- that definition was formally revoked in Document 0100 V2.

THE CDS THRESHOLD: The gate mechanism -- the only door into the platform. Standalone external interface. Every input (human, AI, API, tenant) passes through it before any platform mechanism processes it. Formerly called "External Threshold Gate" -- that name is revoked. The CDS Threshold is the correct and final name.

CONTEXT BACKPACK: A set of mandatory slots every element carries as an intrinsic property. Not documentation -- structure. Elements do not depend on the system remembering to hand context to them. The backpack makes every element self-contained and sovereign.

ZERO FINDINGS (ZF): A mandatory check protocol. Four types: ZF-REGISTRY (check what exists before defining), ZF-SESSION (check current state before acting), ZF-SIMULATION (check coherence before expanding), ZF-PROPAGATION (check coverage before propagating). Running the wrong type produces false confidence -- as dangerous as no check at all.

GPOW: Graduated Proof of Working. Four phases: Concept Proof, Function Proof, Integration Proof, Scale Proof. Done is only declared when Scale Proof is achieved with Platform Governor signature. GPOW is not a testing methodology -- it is a constitutional proof standard.

RATIFICATION STATE: Independent of wiring state. PENDING / APPROVED / HELD / REVOKED. Both ratification state AND wiring state must be true for an element to activate. An element can be technically perfect but not ratified -- it cannot activate.

WIRING STATE: Defined / Wired / Reachable / Current. An element that exists (Defined) is not the same as an element that is connected (Wired), accessible (Reachable), or reflecting live state (Current). Only Current elements are truly actionable.

DYNAMIC COMPLETION: The propagation mechanism for improvements. Every improvement travels BOTH forward (to future work) and backward (to all previously completed work). Backward propagation is as mandatory as forward propagation. This is called the Backward Propagation Imperative.

SWIFT IMPLEMENTATION: A governed mechanism for low-risk progress when ratification is pending. Three conditions required: risk score P1 below 39, P4 above 50, and full context captured. Swift Implementation creates accountability entries -- it does not bypass ratification.

P7 TIME ESCALATION: Time-based escalation for parked items. Fresh (1.0x weight) -- Aging (1.5x) -- Stale (2.5x) -- Critical (4.0x) -- Forced Escalation (blocks all new Swift Implementations until resolved).

CORESPIRAL: The build methodology. Build from core outward. Prove before expanding. Improve before proceeding. Check what exists before creating anything new. Eight sprints declared in Document 0070.

MINI-TREE FILE ARCHITECTURE: A file splitting standard established at end of session. When a text file exceeds 3,500 words or a code file exceeds 200 lines -- it splits into a master file (navigation and context, max 500 words) plus sub-files. Sub-files are created even when short to allow future expansion. Naming: [PARENT-ID]-[NN]_[description]. This standard applies to all files created AFTER 28/06/2026.

PLATFORM GOVERNOR: Yariv Fink. The only human constitutional authority. Cannot be delegated to AI. Signs all ratification decisions as GOV-[YEAR]-[SEQUENCE].

THE PLAYGROUND: A sandboxed space inside CSE where participating platforms meet, share, consult, and debate. Nothing in the Playground is engraved in any platform until consensus is formally declared. Owned by CSE -- not by any participant.

UNIVERSAL INSIGHT ARCHIVE: Cross-platform wisdom that no platform owns. Queryable by all participants. Each platform absorbs through its own gate, translated into its own vocabulary before absorption.

FOURTH ASSUMPTION (Anti-Pattern): The failure mode where a file, message, or output assumes the reader has the session context that only the producer holds. Formally named and declared as a platform anti-pattern on 28/06/2026. Prevention mechanism: File Backpack (this header structure) applied to every file and every communication type.

## Section 7 -- Governing Principles in Full (All 10)

For any reader encountering the platform for the first time.

Principle 1 -- Nothing Stands Alone: Every element must have a place in a pipeline and a corespine before it has a place anywhere else. An element without a declared position is ungoverned.

Principle 2 -- Goal Requirement Is the Only Justification for Existence: Nothing exists because it seemed useful. Everything exists because the goal required it. Traceable to a ratified goal or it does not belong.

Principle 3 -- Existence Is Not Availability. Availability Is Not Actionability: Four wiring states -- Defined, Wired, Reachable, Current. Only Current is truly actionable. The other three are stages toward it.

Principle 4 -- Context Is More Significant Than Content: The same element carries different weight depending on where it sits, what it inherited, and what it serves. Weight is situational. The orchestrator assigns context -- the element does not choose it.

Principle 5 -- Inheritance Is Accumulated, Not Sequential: Every stage inherits from all stages before it -- not just the immediately preceding one. An inheritance break is a structural gap. It must be detected and resolved before implementation proceeds.

Principle 6 -- Context Lives Inside the Element, Not Outside It: Every element carries its own context as an intrinsic property -- the Context Backpack. Elements do not depend on the system remembering to hand context to them. This is the only mechanism that scales.

Principle 7 -- Creation and Audit Are the Same Protocol Run in Opposite Directions: If they are not perfectly mirrored, drift between intent and output is inevitable. Every creation decision has a corresponding audit checkpoint.

Principle 8 -- Outcome Always Appears Near the End: In all step sequences, the outcome is what the sequence earns -- not where it starts. Every protocol presents things in human order: need first, outcome last.

Principle 9 -- Every Registry and Skill Must Have a JSON Schema Before Operational: Promoted from Intelligence Vault (IV-UNIV-0001). No registry or skill enters operational status without a declared JSON schema. Mechanically enforced.

Principle 10 -- The Reader Has No Context You Have Not Given Them: Every file, message, output, and communication is read by a recipient who has zero access to the session that produced it. The producer's context is always temporary. The artifact's context must be permanent and self-contained. Applies to all files, UI text, API responses, agent communications, inter-platform messages, and any artifact that crosses a session or system boundary. The Fourth Assumption -- assuming the reader shares your context -- is a declared platform anti-pattern.
