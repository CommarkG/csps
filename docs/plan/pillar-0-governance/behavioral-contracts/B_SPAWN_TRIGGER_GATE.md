## B_SPAWN_TRIGGER_GATE — a HIGH-SCOPE Opus-agent dispatch requires a recorded verdict before the persistent tab seals it (S089)

**Canonical:** One-tab operating discipline names the pattern — the persistent Opus director tab dispatches
bounded Sonnet-tier `Agent()` build work (via `tools/templates/opus-agent-spawn-template.md`) and performs the
sealing write (stage+verify+commit) itself, never the ephemeral agent, because the two Opus tabs share one
physical git index and a stray commit from the wrong side races and mis-attributes work. This contract closes
the last gap between that pattern being **practiced** and being **mechanically enforced**: a HIGH-SCOPE
dispatch (constitutional / corespine / cross-cutting / depth-ge-4) must be logged in
`tools/data/opus-dispatch-log.yaml` with a recorded verdict — `verdict_recorded: true` + a non-empty
`opus_verdict_ref` — before the persistent tab is permitted to close the loop. `trivial-reversible` dispatches
are exempt; not every `Agent()` call is a governance event.

**Scope:** Applies to Opus-tier dispatches for BOUNDED BUILD work (Sonnet-tier), the counterpart to Haiku scout
scans (which never make governance decisions and are outside this gate). A HIGH-SCOPE dispatch is one touching
`docs/plan/pillar-0-governance/behavioral-contracts/`, `.claude/core-spines/`, `CSPS-NORTH-STAR.md`, or a
depth-ge-4 path in the wider `pillar-0-governance` tree.

**The flow:**
1. **dispatch** — the persistent tab spawns the agent via `opus-agent-spawn-template.md`, declaring a
   `scope_tier`, and logs the dispatch in `tools/data/opus-dispatch-log.yaml` with `verdict_recorded: false`.
2. **return** — the agent returns a verdict + seal-content package (files touched, real command output,
   FAIL→PASS proof, self-declared gaps) per the template's §3 Coverage Manifest. It never stages or commits.
3. **seal** — the persistent tab re-derives the agent's claims from ground truth (B_VALIDATE_BEFORE_ASSUME),
   flips `verdict_recorded: true` + fills `opus_verdict_ref` for HIGH-SCOPE dispatches, then performs the
   atomic stage+verify+commit.

**Honest limitation (do not oversell):** the mechanical gate (`validate-spawn-trigger.mjs`) is a PRESENCE
check — same shape as `validate-consensus-before-code.mjs` and `validate-wiring-sweep-coverage.mjs`. It
confirms the dispatch log carries a HIGH-SCOPE entry with `verdict_recorded: true` this session, not that the
cited `opus_verdict_ref` genuinely reflects independent re-derivation. A hard `PreToolUse` block on the seal
step was not built for the same bootstrapping-self-lock reason B_CONSENSUS_BEFORE_CODE's stricter layer was
deferred.

**Mechanical surfaces:**
- **registry:** `tools/data/opus-dispatch-log.yaml` (per-dispatch scope_tier + verdict_recorded + opus_verdict_ref)
- **template:** `tools/templates/opus-agent-spawn-template.md` (the copy+fill spawn shape + §3 LOGGING STEP)
- **validator (T2):** `tools/validators/validate-spawn-trigger.mjs` — BLOCKING if a HIGH-SCOPE dispatch this
  session lacks a recorded verdict, or if HIGH-SCOPE governance commits exist this session with zero
  dispatch-log activity (registered in `tools/verify.mjs` as `spawn_trigger`)
- **contract:** this entry + composes with B_CONSENSUS_BEFORE_CODE (the choice-confirmation gate a BUILD
  dispatch presumes already passed) + B_IMPLEMENTATION_WIRING_CYCLE (sibling presence-check gate, same
  session) + B_DETERMINISTIC_GATE + B_INSIST_ON_COMPLETION + P-META-032 Provenance Labels (cross-agent
  contracts the template's §7 cites)
