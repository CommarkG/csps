# Schema Registry — Canonical Anchor Index

> **Every valid `schema_anchor:` value must appear here.**
> If an artifact uses an anchor not in this registry: it's an ORPHAN (RP-003).
> Resolution types: `governance-section` | `zmodel-entity` | `typescript-type`

---

## Resolution Types

| Type | Meaning | Example |
|---|---|---|
| `governance-section` | Resolves to a documentation directory or section | `docs/plan/pillar-0-governance/` |
| `zmodel-entity` | Resolves to a ZModel entity in a schema file | `libs/policies/base.zmodel#Tenant` |
| `typescript-type` | Resolves to a TypeScript type/interface | `packages/schemas/intake-event.ts#IntakeEvent` |

## Adding New Anchors

Before using a new `schema_anchor:` value:
1. Check this registry — does the anchor already exist?
2. If no: add it here with `type:`, `resolves_to:`, `spine:`, `l2_domain:`, `description:`
3. If the anchor is for a new artifact type: consider whether it needs a new entry or reuses an existing one
4. Run `validate-nothing-stands-alone.mjs` — it will check anchor resolution once upgraded

**Validator (to build Session B):** `validate-schema-anchors.mjs` — checks every `schema_anchor:` value
against this registry. Unknown anchors = ORPHAN. Pre-existing orphans: advisory; new orphans: BLOCKING.
