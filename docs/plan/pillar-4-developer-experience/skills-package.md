# Skills Package — `packages/skills/`

> **Check what exists. Enhance the ratified thing. Create new only with a justification.**

## What this document locks

The design + codegen pipeline + spec for the platform-owned invokable AI skill set living at `packages/skills/`. Each skill is an [Anthropic Agent Skill](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) folder (`SKILL.md` + supporting files) invocable via slash command and discoverable via the RAG router. **Skills are how operating principles become AI behaviors.**

## Why this exists

A principle in `principles.yaml` is a string. An AI assistant sees the principle if it remembers to load `AGENTS.md`. That's a memory layer; memory layers fail.

A **skill** at `packages/skills/<name>/SKILL.md` is mechanically discoverable: the RAG router loads it when the user types `/skill-name` or when context-relevance matches the skill's `description` field. This is the principle's mechanical layer — the principle text becomes a callable behavior the AI can invoke.

Per AGENTS.md hard NO ("Memory alone doesn't change behavior; only mechanical layer does"): the `packages/skills/` folder IS the mechanical layer for operating principles.

## The starter skills (generated from `principles.yaml`)

Each skill is generated by `pnpm principles:codegen` from a corresponding row in `principles.yaml`. The skill's `description` references the parent principle ID.

| Skill | Slash command | Principle backed | Output |
|---|---|---|---|
| `pcr` | `/pcr <topic>` | P-OP-003 | Canonical Pros / Cons / Recommendation 3-block markdown |
| `wip-check` | `/wip-check` | P-OP-002 (FWWS) | Queries in-flight ledger; reports threshold status |
| `reuse-check` | `/reuse-check <terms>` | P-OP-001 (Reuse-first) | Catalog similarity search; top-5 matches with cosine scores + cited frontmatter |
| `batched-plan` | `/batched-plan` | P-OP-004 (Batched execution) | Structures upfront-acceptance proposal for N≥3 similar operations |
| `audit-self` | `/audit-self` | P-META-001 | Runs the meta-audit (audit-the-audits) on demand; reports under-enforced principles |
| `stewardship-review` | `/stewardship-review` | P-META-004 | Surfaces every pending-protocol / pending-review / active-stale item |
| `learning-loop-extract` | `/learning-loop-extract` | P-META-005 | Captures insights / errors / gaps / decisions / near-misses; routes to LearningLoopItem ledger |

Both `stewardship-review` and `learning-loop-extract` shipped as stubs in S002 at `packages/skills/<name>/SKILL.md`.

## Skill folder structure

Per [agentskills.io](https://agentskills.io/) spec:

```
packages/skills/pcr/
├── SKILL.md                  # Frontmatter + skill body (the prompt template)
├── examples/
│   └── trivial-decision.md   # Skipping criterion example
└── references/
    └── industry-lineage.md   # Toyota A3 + Amazon working-backwards links
```

Per pillar-3 sandboxed-skill-governance.md, every skill's `SKILL.md` declares capabilities:

```yaml
---
name: pcr
description: When the user asks for help with a non-trivial decision OR proposes >1 option, produce canonical Pros / Cons / Recommendation 3-block output. Skip on trivial-reversible per P-OP-003 counterweight.
allowed_tools: []
allowed_subagents: []
allowed_outbound_hosts: []
allowed_db_operations: []
sensitive_data_access: false
backed_by_principle: P-OP-003
generated_by: principles-codegen
generated_from: packages/principles/principles.yaml#P-OP-003
last_generated_at: 2026-05-02T19:00:00Z
---

# /pcr — Pros / Cons / Recommendation

[skill body — the prompt template the AI uses when invoking this skill]
```

## The codegen pipeline

`packages/principles/codegen.ts` (skeleton in S002; full implementation week 2 per build-order):

```
principles.yaml
     │
     ▼
codegen reads each row matching `generates_skill: true`
     │
     ▼
For each principle:
  - Read the row's `skill_template` field (the SKILL.md template)
  - Substitute principle ID, description, counterweight, examples
  - Write to packages/skills/<id>/SKILL.md
  - Update generation timestamp
  - Verify `enhances:` or `created-new-because:` declared
  - Validate frontmatter against agentskills.io spec
     │
     ▼
CI fails if generated skill drifts from principles.yaml row
```

`pnpm principles:codegen` MUST be run after every `principles.yaml` mutation. Per AGENTS.md hard NO: "Never modify `packages/principles/principles.yaml` without running `pnpm principles:codegen` and committing both."

## Cross-vendor compatibility

The Anthropic Skills spec is open ([agentskills.io](https://agentskills.io/)). The same `SKILL.md` works in:
- Claude Code (the home environment)
- OpenAI Codex (loads SKILL.md per agentskills.io spec)
- Cursor (loads SKILL.md per agentskills.io spec)
- Other adopters of the spec

This means the platform's principle-enforcement layer is **vendor-portable**. If we switch AI vendors, the skills move with us; they don't need re-authoring.

## Skill design discipline

Per the agentskills.io spec recommendations:

1. **Front-load keywords in `description`** — the RAG router uses ONLY the description field to decide whether to load the skill. "Use when..." / "Triggers on..." / "Output is..." beats prose.
2. **One skill per principle** — composition emerges from invoking multiple skills, not from monolithic skills
3. **Skill body is a prompt template, not code** — the skill's job is to instruct the AI; the AI executes
4. **`references/` sub-files** — long examples / industry lineage / edge cases live in `references/`; the skill body links to them via relative path; the RAG router loads sub-files on demand (cuts root context use)
5. **No skill should require sensitive_data_access** — by design, principle-skills are introspective; if a skill needs sensitive access, that's a signal it's the wrong abstraction

## Skill vs sub-agent (when to use which)

Per CSPS conventions (clarified S002):

- **Skill** — invoked by the AI itself in-context; lightweight; prompt-template-shaped; cross-vendor
- **Sub-agent** — spawned as a separate agent process; has its own context window; used for parallelizable independent queries OR to protect main context from large result sets
- Use a **skill** for principle-enforcing behaviors (PCR, reuse-check, audit-self)
- Use a **sub-agent** for research / extensive code exploration / parallel analysis

## Anti-patterns

1. **Hand-authoring a skill that should be codegenerated** — refused; if the skill's content derives from principles.yaml, it must be generated; CI checks via timestamp + content hash
2. **Skill bypassing capability declaration** — refused; pillar-3 sandboxed-skill-governance enforces
3. **Skill duplicating an existing skill** — refused at platform:skill generator (catalog-first UX surfaces existing match)
4. **Description prose >1024 chars** — refused; agentskills.io spec + frontmatter validator
5. **Skill that requires the AI to remember to invoke it** — wrong design; skills should be RAG-discoverable from context, not memory-triggered
6. **Skill drifting from its principle source** — refused; `audit-skill-codegen-drift` (PR-blocking) catches via hash diff

## Enforcement

- `principles.yaml#P-OP-001` through `#P-OP-004` (the operating principles backing each skill)
- `principles.yaml#P-META-001` through `#P-META-007` (meta-principles; some generate skills, some are pure-architectural)
- `audit-runner.md#skill-codegen-drift` (PR-blocking; generated skill content matches source row)
- `audit-runner.md#skill-frontmatter-completeness` (PR-blocking)
- `tools/generators/skill/index.ts` (`platform:skill` generator)
- `packages/principles/codegen.ts` (the codegen pipeline)
- `packages/principles-mcp/` (the MCP server that exposes principles + skills as resources)
