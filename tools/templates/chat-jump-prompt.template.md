# Chat-Jump Prompt Template

> Use this template at every session-close to generate the cross-chat handshake. Two output files per close: minimal (paste-target for new AI) + detailed standalone (paste-target for user before pasting to new chat). Per B_MUTUAL_UNDERSTANDING_VALIDATION (P-META-014).

## Output 1 — Minimal (paste to new chat as user message)

**Filename:** `_handoff/VAULT/chat-jump-prompt-S<NNN>-to-S<NNN+1>.md`

**Format (exactly this shape):**

```markdown
# YOU ARE S<NNN+1> — IDENTITY BANNER

Confirm in your first reply: "✅ I am S<NNN+1>, picking up from S<NNN>-close at <iso8601-utc>".

Workspace: c:\Users\finky\Desktop\Claude Code\Csps
Verify: `Glob docs/plan/pillar-*/README.md` returns 7 results before any §3 work.

## First action MANDATORY

Read `docs/plan/_handoff/HANDOFF-S<NNN>-to-S<NNN+1>.md` §0 and execute the §0 step list.

## Receipt signature MANDATORY

Format: `S<NNN+1>-AI-receipt-<iso8601-utc>-against-S<NNN>-AI-attest-<original-attest-iso>`

## §17 attestation acknowledgement MANDATORY

Per-line ✅ on prior session's attestation OR ❓→BLK-S<NNN+1>-* (raised as blocker).
```

## Output 2 — Detailed standalone (~250-600 words; saved for user re-access)

**Filename:** `_handoff/VAULT/chat-jump-prompt-S<NNN>-to-S<NNN+1>-detailed.md`

**MANDATORY SECTIONS (8) — chat-jump-prompt-8-mandatory-sections validator enforces presence:**

### Section 1 — Identity banner (writer-side)
Asserts WHO YOU ARE (S<NNN+1>) at the very top + confirmation expected in first reply. Per S006 turn 4 absorption: writer-side identity-banner is the first half of the bidirectional identity-confirmation gate.

### Section 2 — Workspace + verification commands
Path to CSPS workspace + concrete verify commands (Glob / Grep / Read / pnpm verify) that new AI must run before refusing on "wrong workspace" warnings (parent CLAUDE.md known false-positive trap per memory entry).

### Section 3 — HANDOFF §0 paste-target (self-contained)
Copy of HANDOFF §0 content embedded inline so new AI can read without fetching the handoff first.

### Section 4 — Post-close addenda references (if any)
List of §24+ post-close addendum sections in the handoff (work that landed after original close-attest signature).

### Section 5 — Governor-prompts log pointer
Path to `_handoff/VAULT/governor-prompts/S<NNN>.md` with one-line summary of cardinal-flagged GP count.

### Section 6 — HPFA evidence pointer
Path to HANDOFF §<X> §10.0f HPFA results block + summary of overall_status (PASS / FAIL with carry-forwards).

### Section 7 — All carry-forwards with explicit reasons
Table or list: every item NOT closed in S<NNN> + reason carried (foundation-stability defer / dependency-on-week-N / ratification-pending / scope-deferred-with-reason).

### Section 8 — Cardinal directives verbatim
Cross-link to user-intents.md S<NNN> section with ≥3 most load-bearing cardinals (verbatim quotes; not paraphrased).

### EXPLICIT ALIGNMENT-QUESTIONS SECTION (mandatory per B_MUV S005 turn 28)

≥10 numbered questions covering:
- Scope-confirmation (Q1-Q3): ratify §3 scope / ordering / priorities
- Interpretation-of-cardinals (Q4-Q5): confirm understanding of cardinal directives
- Engraving-confirmation (Q6-Q7): ratify newly-engraved disciplines
- Verification-state (Q8-Q9): pnpm verify state + carry-forwards
- Open-question (Q10-Q11): ADR candidates / open frontiers
- Process-confirmation (Q12+): user-required actions before §3 work

**New AI MUST answer all questions in first reply BEFORE proceeding with §3 work.**

## Receipt signature format (reader-side — second half of identity-confirmation gate)

```
S<NNN+1>-AI-receipt-<ISO-8601-UTC>-against-S<NNN>-AI-attest-<original-attest-ISO>-S<NNN>-close
```

Validator `session-receipt-signature-format` checks:
- Has both session IDs (matching pair)
- Both timestamps ISO-8601 UTC
- Hyphen-separated structure
- "AI-receipt" + "AI-attest" tokens present

## Cross-chat iteration loop (the I→I closure)

1. Closing-AI generates both paste-targets at session-close
2. User pastes Output 1 to new chat
3. New AI responds with §17 attestation + alignment-question answers + receipt signature
4. User brings new AI's response BACK to current closing-chat
5. Closing-AI audits the new AI's response:
   - Refines prompt template if alignment-questions surfaced gaps
   - Replies with clarifications OR alignment-confirmed-explicit acknowledgment
6. Iterate Steps 4-5 until alignment-confirmed-explicit (no more clarifications)
7. New AI proceeds with §3 work AFTER alignment-confirmed-explicit

This iteration is the cross-chat handshake — without it, the I→I loop doesn't close + drift propagates.

## Validators (atomic per FSE; impl week-4)

- `chat-jump-prompt-identity-banner-present` (writer-side check)
- `session-receipt-signature-format` (reader-side check)
- `chat-jump-prompt-8-mandatory-sections` (sections 1-8 + alignment-questions present)
- `alignment-questions-section-required-on-high-stakes` (≥10 questions when session was substantive)
- `cross-chat-handshake-completion` (alignment-confirmed-explicit reached within N iterations)
